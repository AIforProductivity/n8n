Step 1 - Replace the default Nginx site

Open the default site:

sudo nano /etc/nginx/sites-available/default

Replace everything with this:

server {
    server_name n8n-template.imawais.engineer;

    client_max_body_size 100M;

    location / {
        proxy_pass http://127.0.0.1:5678;

        proxy_http_version 1.1;

        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";

        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-Host $host;
        proxy_set_header X-Forwarded-Proto https;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Real-IP $remote_addr;

        proxy_read_timeout 3600;
        proxy_send_timeout 3600;
        proxy_connect_timeout 3600;

        proxy_buffering off;
    }

    listen 443 ssl http2;
    ssl_certificate /etc/letsencrypt/live/n8n-template.imawais.engineer/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/n8n-template.imawais.engineer/privkey.pem;

    include /etc/letsencrypt/options-ssl-nginx.conf;
    ssl_dhparam /etc/letsencrypt/ssl-dhparams.pem;
}

server {
    listen 80;
    server_name n8n-template.imawais.engineer;
    return 301 https://$host$request_uri;
}

Save and exit.

Next improvements (recommended)

I recommend making these before cloning the VM:

1. Create a .env file

Move all configurable values out of docker-compose.yml, including:

PostgreSQL password
N8N_ENCRYPTION_KEY
N8N_HOST
WEBHOOK_URL
N8N_EDITOR_BASE_URL
Time zone

Then reference them in docker-compose.yml with ${VARIABLE_NAME}. This lets you clone the VM and only edit a single file.

2. Pin the n8n image version

Instead of:

image: n8nio/n8n:latest

use a specific release, for example:

image: n8nio/n8n:1.107.4

(or whichever version you decide to standardize on). This prevents unexpected upgrades.

3. Add automated PostgreSQL backups

A simple nightly backup script and cron job that writes timestamped SQL dumps to a backup directory.

4. Add Docker log rotation

Prevent container logs from growing indefinitely by configuring Docker's logging options.

5. Add deployment and update scripts

Create small scripts such as:

deploy.sh
update.sh
backup.sh
restore.sh

to simplify routine operations.

6. Create a cloning checklist

When creating a new VM from this template, you'll only need to:

Clone or image the VM.
Assign a new Azure public IP.
Create a new DNS A record.
Update the .env file with the new hostname (and any new secrets, if desired).
Restart the stack with docker compose up -d.

That keeps each deployment consistent and minimizes manual edits.

Once you've confirmed n8n is reachable, these refinements will make the VM a clean, reusable production template.
